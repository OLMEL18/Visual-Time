Offline reference

Visual Time app map

Visual Time turns an accurate monotonic countdown into a calm physical signal: warm sand moves through a custom-drawn hourglass. One Compose activity coordinates Setup, Running, Paused, and Finished without a navigation graph.

Snapshot: commit c7b64b0 · generated 2026-10-23. Later commits can make paths or behavior drift from this map.

One real action: start 25 minutes

The four pieces to remember

Timer engine

timer/TimerEngine.kt uses elapsed-realtime anchors to derive remaining milliseconds and normalized progress. Pause stores accumulated elapsed time; restart resets it. Animation frames never determine time.

ViewModel

VisualTimeViewModel.kt owns the live session and state transitions. Search for startDuration, publishSnapshot, pause, and restart.

Canvas renderer

ui/hourglass/HourglassCanvas.kt consumes only progress and isFlowing. HourglassGeometry.kt owns the shared wall profile, clipped sand paths, volume lookups, and fixed stream origin.

Local persistence

data/RecentDurationsRepository.kt reads/writes one DataStore preference. RecentDurationsPolicy.kt keeps the three-item unique MRU rule pure and testable, including missing versus present-empty storage.

Three-stop reference route

  1. Input and visible state: open app/src/main/java/com/kisss/visualtime/ui/VisualTimeScreen.kt. Search for VisualTimeScreen, SetupControls, and SharedHourglass. This is where taps become ViewModel calls and immutable UI state becomes panels plus Canvas parameters.
  2. Authoritative behavior: open app/src/main/java/com/kisss/visualtime/VisualTimeViewModel.kt. Search for startDuration and publishSnapshot, then follow calls into timer/TimerEngine.kt. This boundary keeps countdown correctness independent from redraw frequency.
  3. Visible result and saved convenience: open ui/hourglass/HourglassCanvas.kt and ui/hourglass/HourglassGeometry.kt for rendering; open data/RecentDurationsRepository.kt and RecentDurationsPolicy.kt for the quick-start list.

To change this, start here

  • Countdown arithmetic or pause/restart semantics: TimerEngine.kt, then TimerEngineTest.kt and VisualTimeViewModelTest.kt.
  • Hourglass silhouette, wall contact, sand volume, or stream: HourglassGeometry.kt; presentation loop and drawing order: HourglassCanvas.kt.
  • Three recent durations or seeding rules: RecentDurationsPolicy.kt, then RecentDurationsRepository.kt and RecentDurationsPolicyTest.kt.
  • Setup, overlays, shared control anchors, or About entry: VisualTimeScreen.kt; About content and external links: AboutDialog.kt and res/values/strings.xml.
  • Foreground/background completion delivery: start in completion/ and feedback/; composition begins in MainActivity.kt.

A practice to reuse

Separate the authoritative model from its visual projection, then verify each at the right boundary. In this project, scope.md protected “make time visible” as the kernel; TimerEngineTest.startAndMidpointUseMonotonicElapsedTime proves the clock model; the Slice 2 phone checkpoint proved the Canvas looked convincing on the real device. This pattern transfers well to another small app: define the observable result, isolate the rule that must remain correct, and schedule an early real-device check for the part that cannot be settled on paper.

Build and run again

  1. Use JDK 17 and Android SDK Platform 37; keep the SDK path in ignored local.properties.
  2. From the repository root run .\gradlew.bat testDebugUnitTest assembleDebug.
  3. Install app\build\outputs\apk\debug\app-debug.apk on an Android 8.0+ device. The primary verified device was a Redmi Note 9 Pro running Android 12/API 31.
